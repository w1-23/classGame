# classGame：按图三制作地图与关卡场景

日期：2026-11-22。视觉基准：`reference/target-map.png`。

> 仓库集成状态（2026-11-22）：`assets/vector/` 中的 10 个 SVG 已导入运行时目录 `assets/map-art/vector/`，地图与 Phaser 跑酷场景均已实际加载。集成记录见同目录 `integration.json`。

## 0. 本包怎么用

先打开 `preview.html`，再对照 `reference/target-map.png`。图三的山、树、河、桥、路与右侧场景预览，主体由 Canvas 绘制；主角来自项目已使用的 Kenney Toon Characters。

本包提供可复用的原始绘制代码、自制同风格矢量基件、角色动作帧、素材检索入口和导入索引工具。它是交付给实现者的视觉与代码参考，不是已接入仓库的完整游戏，也没有增加正式教材题目。

关键文件：

- `preview.html`：独立预览，图片嵌入，无运行时远程脚本。
- `reference/map-fragment.html`：上一轮原始示意，完整保留，不改它作为基准。
- `src/reference.js`、`src/reference.css`：从原示意抽出的代码与样式。
- `src/map-primitives.mjs`：可独立复用的树、石、云、椭圆和多边形绘制函数。
- `src/palette.json`：图三的浅色配色。
- `src/scene-themes.example.json`：地图和局内共同使用的主题配置示例。
- `assets/vector/`：按相同色板制作的 SVG 基件；预览仍使用原 Canvas，SVG 是可选导入材料。
- `assets/characters/`：图三使用的三个奔跑帧；保留其 Kenney 许可证。
- `tools/make-asset-catalog.py`：把实际素材文件做成可浏览索引与 JSON 清单。
- `docs/asset-sources.json`：已核对的外部素材入口；候选包没有假装下载进本包。

## 1. 当前画面与图三差在哪里

1. 少量关卡被铺满很宽的画布，路线过长，节点之间缺少内容。
2. 道路过粗，带公路式中线；图三是较细的奶油色步行小径。
3. 高饱和、粗黑描边的平台游戏灌木，与低饱和、无粗描边的地形风格冲突。
4. 桥是独立摆在河面上的木块，没有承担道路连接两岸的关系。
5. 图一的大部分场景元素只是重复放置，没有围绕河流、山体与路径安排。

实现时保持图三的轮廓、配色、地图密度与组件比例，教材信息可以替换，地图风格不要重新猜测。

## 2. 找素材：先看真实图，再建立映射

### 2.1 先复用项目现有角色

先查看实际仓库文件，不重复寻找人物：

```bash
rg --files assets/kenney/characters
rg --files assets/kenney/licenses
rg --files vendor/kenney
```

本包含 `adventurer-run0.png`、`adventurer-run1.png`、`adventurer-run2.png`。项目里的待机、受挫与庆祝帧可继续使用。绘制时按脚底锚点放置，不把整张 PNG 的外接矩形底边直接当作脚底；透明边距需要在索引中检查。

### 2.2 外部素材按这个顺序找

1. **Background Elements Remastered**：https://kenney.nl/assets/background-elements-remastered 。Kenney 作者发布页：https://opengameart.org/content/background-elements-redux 。官方标注 90 个 2D 元素、CC0；作者说明包含独立 PNG、Spritesheet、Vector 与样例背景。用于候选远山、树、围栏、建筑等，挑选单个元素。
2. **Foliage Pack**：https://kenney.nl/assets/foliage-pack 。作者发布页：https://opengameart.org/content/foliage-pack-100x 。作者说明包含不同季节、不同风格的植物、独立 PNG、矢量与额外高分辨率版本。只选与图三匹配的平涂、弱描边子集。
3. **Toon Characters**：https://kenney.nl/assets/toon-characters 。当前角色来源，官方标注 CC0。优先复用工程现有动作帧。
4. **Map Pack**：https://kenney.nl/assets/map-pack 。作者发布页：https://opengameart.org/content/map-pack-180-assets 。有地形、道路、角色与地图物件，适合少量地标候选；图三的曲线路线继续由代码绘制。

以上网页与作者说明已核对；本轮没有下载这几个完整 ZIP、没有逐张审看，包内目录必须以实际解压结果为准。不要编造 `tree_01.png` 等源文件名。不要用搜索缩略图、网页预览截图替代素材原文件。

### 2.3 下载之后先生成素材索引

通过官方页面 Download 取得实际 ZIP，解压到项目 `vendor/kenney/<真实包名>/`，保留原包和 LICENSE。不要猜测 CDN 的下载地址。

```bash
python tools/make-asset-catalog.py vendor/kenney --out asset-catalog
```

脚本需要 Pillow。输出 `asset-catalog/index.html` 和 `asset-catalog/catalog.json`。先打开索引逐张查看，再把选择结果写成素材映射：用途、真实路径、源包、许可证、尺寸、透明边距、目标主题。屏幕上有预览与文件名，才能判断自己选的是树、灌木、地形块还是整张背景。

### 2.4 选用标准

- 环境元素无粗黑外轮廓；人物沿用现有角色可保留其自身造型。
- 使用平涂、少量两色明暗，不引入写实照片或像素地形。
- 颜色符合本包色板，必要时从矢量源统一换色；透明 PNG 不进行破坏轮廓的硬抠。
- 同一主题内保持视角、阴影方向、材质细节一致；同一作者不等于同一风格。
- 自定义场景图形优先 Canvas/SVG；PNG 按最大显示尺寸选取足够分辨率，保留宽高比。

## 3. 地图绘制规则

### 3.1 保留比例与密度

参考浅色配色：草地 `#deedcb`，树冠 `#58865b / #8db67b / #366947`，小径 `#fbebbd`，路缘 `#b9bc8c`，河水 `#93cbd4`，河岸 `#d7f3ed`，文字 `#233d32`，面板 `#fffef7`。

原稿基准：节点直径 48 CSS px，道路外宽 23 px、内宽 17 px，角色约 59×80 px。适配时保留比例。课堂触控可整体放大节点与间距；不要只把背景和道路横向拉伸。

单元只有 2–3 个关卡时，让相邻单元连续显示，当前单元只负责定位与高亮。一个视野争取容纳约 8–12 个真实节点。如果必须单独展示少量关卡，改用紧凑构图。不能把 3 个节点撑满巨幅画布，也不能伪造关卡凑满画面。

### 3.2 由后向前绘制

1. 大块陆地区域与柔和草地明暗。
2. 河流与浅色岸线，先形成完整地形。
3. 山体、树林、岩石与地标。
4. 小径外缘，再画奶油色路面。端点与转折圆滑，不画公路中线。
5. 过河位置的桥面、木板和少量护栏。
6. 关卡节点及已完成标记。
7. 主角、当前位置提示和选关信息。

素材布置先安排路径附近的空白，再布置景物。节点周围保留安全区；树冠不能挡住编号，主角脚底与节点对应。用少量不同大小和形状的树簇构成区域，不在画布上机械平铺同一张草丛。

### 3.3 复用代码的位置

- `tree / rock / cloud / oval / polygon`：直接复用基础造型。
- `curvedPoints / strokeRoute`：平滑小径。原示意采用样条曲线经过节点。
- `prepare`：按实际容器尺寸与像素密度重绘，避免拉伸低分辨率画布。
- `drawMap`：地图地形绘制。
- `setTraveler / moveTo`：角色沿同一条路线移动。
- `drawScene`：右侧简化场景预览的绘制参考，不是完整跑酷引擎。

节点、道路与主角共用一份路线几何。正式版可以计算累计弧长，让角色按实际路程匀速移动；原稿按采样点播放，仅作为示意。

### 3.4 桥必须接通两岸

原示意桥段写死在 `route.slice(32*6, 32*7+1)`，只适用于这张示例图。正式版改为布局数据中的桥段，或者求道路与河带的相交区间。沿道路方向铺桥，木板横跨桥面，桥两端超出水面落到岸上。

必须检查：路线在河上没有裸露的土路；桥面与路线连续；木板方向正确；两端没有悬空。不要将横版平台的独立木块当作俯视桥梁。

## 4. 关卡内跟随区域变化

地图与关卡共享 `themeId`，分别用适合各自视角的绘制器：地图采用示意式俯视，选路游戏采用朝前看的透视。共享配色、植物种类、地形与道路材质，不把俯视地图图片直接拉长成跑酷背景。

每个主题至少改变五项：天空/光线、远景轮廓、地面/水面、道路材质、两侧景物。

| 主题 | 地图表现 | 选路关卡内表现 |
|---|---|---|
| 森林 | 树簇、草坡、小径 | 天空、远山、树群、林间土路 |
| 溪谷 | 河流、跨河桥、河岸树 | 两侧水面、河岸、向远处收缩的木栈道与栏杆 |
| 山谷 | 石坡、山峰、曲折山路 | 远山、两侧岩壁、石质路面 |
| 果园 | 暖色树冠、田块 | 暖色光线、果树、落叶与土路 |
| 海岸 | 海湾、沙岸、码头 | 海面、沙岸、木道、远处帆影 |
| 雪原 | 白色地面、松树、冰湖 | 淡蓝天空、积雪山体、雪松与雪径 |

同一关的地图预览与真实场景要读取同一个主题对象。不能只更改“地形：溪谷”的文字或右侧预览，实际游戏仍然加载森林背景。

局内绘制顺序：天空 → 远山 → 中景树群/岩壁 → 地面与道路 → 路边景物（从远到近）→ 答案门 → 主角 → 题目牌/反馈/操作栏。若使用 Phaser 的独立对象，深度排序应保证相同遮挡关系。

三条答案路线、门牌和题目文字保持稳定可读。树、岩石、桥栏避开答案安全区。装饰物与答案门共用同一套透视计算，按距离缩放，不能固定像素位置乱放。角色不能盖住选项文字。选路模式取消沿路金币。

翻牌、听音、拼装、诗词和对战也读取同一主题：改变卡桌/任务台/背景与边缘地标，保留稳定的题目和操作区域。诗词改为随机填空，不恢复强制朗读。

## 5. 从示意接入正式游戏时，替换这些内容

- 固定 36 关、每 12 关一页、每 4 关一个主题：改为真实教材和关卡数据。
- 示例词汇、诗句和预置完成记录：替换为正式题库与存档。
- “演示通关与前进”按钮：只保留在预览中，正式界面删除，由真实通关事件触发保存和动画。
- 内存中的 `records`：接入正式持久化存档。
- 桥段、节点与景物坐标：移到地图布局配置；不要把公式按关号硬编码。
- 字体、图标与样式：接入项目规范，保留原稿配色和几何比例。
- 页面退出：取消 requestAnimationFrame，断开 ResizeObserver，移除主题监听；游戏退出也要清理计时器和语音。

课堂跳关只改变选中关卡和角色位置，不能补记沿路成绩；不同游戏的关卡进度分别保存。

## 6. 最小可验收交付

1. 用真实教材内容做一段连贯路线，保持图三的节点密度与小径比例。
2. 提交素材索引、实际选用清单和保留的许可证。
3. 先完成森林、溪谷、雪原三套主题，每套都提交同一关的“地图位置＋局内截图”。
4. 检查桥连通两岸、数字清楚、角色不遮挡答案、装饰不进入答案通道。
5. 分别检查宽屏与竖屏；宽屏不把少数节点拉成巨幅空路，竖屏不挤压标题和门牌。
6. 实际答题通关才能点亮节点并推进；返回和重启后进度一致。

本包完成了原代码提取、文件结构与资源引用检查、SVG 语法检查；原示意此前已做最小 DOM/计时器逻辑复现。此次不把这些检查表述成完整浏览器视觉回归或 Windows 安装验收。
