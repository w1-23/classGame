# 48首诗词填空包：接入与审核说明

## 本次交付的实际内容

`content/poetry-48.json` 含 **48 首古诗、6 个主题单元、48 个关卡、384 个不同空位变体**。每关对应一首诗，不再把同一首诗拆成很多“空关卡”。每首 4 个题组，每组 2 个备选空位；每次从每组抽 1 题，最终玩 4 题。

另保留每关 4 条 `questions` 作为旧引擎兼容数据，48 关默认题合计 192 条。**384 是题库变体总数，不是每局题数，也不是诗歌首数。**《咏鹅》有 3 句实质描写，允许 2 个题组采用同一句的不同空位；其余篇目采用 4 个不同原句。

|主题|关卡|数量|建议场景|
|---|---|---:|---|
|春日芳菲|1–8|8首|春日林地、花径|
|四时风物|9–16|8首|荷塘、秋林、梅园|
|山川行旅|17–24|8首|山谷、江流、竹林|
|乡思友谊|25–32|8首|月下村落、渡口|
|田园童趣|33–40|8首|田野、池塘、村居|
|学思咏物|41–48|8首|草原、竹石、雪梅|

场景名称与 `sceneHint` 是接入建议，内容 JSON 不会自行改变画面；仍需由游戏的场景配置和资产加载器消费。主题不是教材单元，也不是官方年级编排。

## 文件

- `content/poetry-48.json`：主内容包，保留原有 `poems[].cloze`，增加完整 `units[].lessons`。
- `content/poetry-48-sources.json`：逐首来源、固定修订号（来源可取得时）、采用异文、核对状态。
- `content/build_poetry_pack.py`：可复现构建脚本，48 首正文和全部空位/干扰项均在脚本中显式编写。
- `content/validate_poetry.py`：独立内容校验器，不依赖游戏运行或网络。
- `content/validation-report.json`：对实际输出数据运行校验的结果与 SHA-256。
- `docs/content/poetry-48-catalog.md`：逐首完整正文、来源、192 个题组/384 个变体及答案，方便内容人员复核。

## 审核状态与来源边界

核对日期为 **2026-11-22**。48 首均实际打开并核对了所列来源，古诗文本以维基文库所载古代原文为主；《悯农》（锄禾篇）和《石灰吟》采用香港教育局公开材料中列出的古代正文。仅取古诗本身，不复制现代赏析、翻译、练习册、配图或录音。

状态统一为：

```json
{
  "sourceChecked": true,
  "teacherReviewed": false,
  "reviewed": false,
  "auditStatus": "source_checked_teacher_pending"
}
```

`sourceChecked` 表示本次源文核对，不代表已由任课教师审批，不代表与某年级某出版社教材逐课对照，也不代表任何下载音频已经验收。语义与年龄适宜性仍需任课教师按实际班级选择。

文字有版本差异时，必须把整个采用版本固定下来。例如《静夜思》采用来源“唐诗三百首”栏；《墨梅》采用“列朝诗集”栏；《山行》用“白云生处”；《石灰吟》用所列教育局版本“千锤万击”“粉骨碎身全不怕”。这些都写进 `editionNote`，已知有效异文没有被放进干扰项。学校用本不一致时，应同时修改原文、题干、答案、说明与来源，不能只改展示文字。

古代原文的公版性质不延伸到来源网站的现代编辑说明、音频、插画或版式。题目和干扰项为本次新编，不从现代练习册复制。没有为不存在的录音生成虚假的文件路径。

## 数据契约

每一道题在进入游戏前就有完整元信息：

```js
{
  id: "poem-chunxiao-g1-v1",
  poemId: "poem-chunxiao",
  title: "春晓",
  author: "孟浩然",
  dynasty: "唐",
  line: 0,                   // 原诗分句的零基索引
  lineText: "春眠不觉晓",     // 反馈时展示完整原句
  before: "",
  answer: "春眠",
  after: "不觉晓",
  distractors: ["冬眠", "秋风"],
  variantGroupId: "poem-chunxiao-g1",
  sourceUrl: "https://zh.wikisource.org/wiki/春曉_(孟浩然)"
}
```

必需约束为 `before + answer + after === lineText`。不能在正式出题前把 `lineText` 显示在选项上方泄露答案；答案揭晓、复习页才显示完整句。

每个 `lesson` 同时提供：

```js
{
  poemId: "poem-chunxiao",
  questions: [/* 兼容旧引擎的4条完整题目 */],
  questionPool: [/* 4组×2变体=8条完整题目 */],
  questionsPerRun: 4,
  samplingPolicy: "one_variant_per_group_then_shuffle"
}
```

## 接入顺序

1. **按内容包 ID 替换旧诗词包的入口。** 新 ID 为 `poetry-cloze-48-v1`，旧 ID 是 `poem-morning`。将 manifest 中诗词填空的路径和 ID 指向新包，避免旧两首包仍被 `packs.find(p => p.poems)` 首先选中。不要同时加载两个包却继续依赖“第一个含 poems 的包”。
2. **优先使用显式 `units`。** 此包已经完成 6×8 分关。不得再次按 `poems[].cloze` 每 2 题拆关，否则会把 48 首重新膨胀成 192 个小节点，偏离本次一首一关的设计。
3. **让 `normalizeLesson` 透传新字段。** 至少保留 `poemId`、`questionPool`、`questionsPerRun`、`samplingPolicy`。现有白名单如果只返回 `items/questions/title`，新池会被丢掉。
4. **开局只生成一次本局题目。** 从每个 `variantGroupId` 各抽一个变体，再打乱 4 题的顺序；对每题 `[answer, ...distractors]` 再独立洗牌。使用同包 `runtime` 目录的 `buildPoetryRound` 适配逻辑。渲染、暂停恢复、重放读音均复用本局数组；不能在 render 过程中重抽。
5. **任务数按本局真实数组显示。** 每局 4 题；总内容数明确写 48 首/48 关/384 个备选空位。不要拿空的 `items.length` 算出“1道诗词填空”，也不能把 8 个变体全播完后仍显示“4题”。
6. **进度加版本空间。** 旧包关卡与新包编号不是一一对应，不直接继承旧关卡序号。至少用 `packId + gameId + lesson.id` 作为新进度键。保留旧记录供迁移检查，不伪造新关完成状态。
7. **把填空文本和朗读能力分开。** 此包没有 audio/lineAudio，且用户已选择以填空为主。内容校验只在某模式确实要求录音时才检查音频。不要为了通过旧校验器写入不存在的 WAV 路径，也不要把 `reviewed:false` 改成 `true` 伪造审批。

重玩应重新生成会话随机种子。真正的随机允许偶然重复；如产品要求连续两次一定不同，应比较上一局题目/选项顺序指纹并重新抽样，而不是循环轮换固定答案位置。

## 独立验证

在整改包根目录运行：

```sh
python content/build_poetry_pack.py
python content/validate_poetry.py --report content/validation-report.json
```

校验覆盖所有 384 个变体：ID 与元信息、原句复原、选项唯一性与等字数、题组数量、题池与兼容题一致性、6×8 关卡引用、重复空位、来源字段、明确的待教师审核状态，以及部分已知异文不能成为错误选项。

这是内容结构校验，不能替代任课教师的语义/教材适配审核，也没有运行 Windows 安装、真实扬声器播放或整场游戏验收。随机规则与游戏状态验收另见 runtime 说明。

## 建议游戏内表现

每一关以当前诗的主题场景为底图，题干为居中的单句填空，3 个候选词保持同等视觉权重。选对时在场景内短暂补全诗句并给一个轻反馈，继续下一题；选错先补出正确词，再继续，不弹出必须点“下一题”的整屏遮罩。结算时展示完整原诗与本轮错题，提供“复习本诗”“下一关”“返回地图”。

默认不以本内容包调用语音评分或要求先完成朗读。以后添加可用录音时，可以提供独立“听一遍”辅助入口，但它不应阻塞填空通关。场景变化由关卡选中同一 `theme/sceneHint` 驱动地图预览和实玩，保证地图与关内一致。
